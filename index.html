My Skills & Abilities

Skills development

This final project of my degree program has allowed me to practice, hone, and prove my abilities as a software developer. This project began from previous coursework in my program. In CS 310 – Collaboration and Team Project, we partially developed a C++ program that stored student, song, artist, and album information. The program worked as a jukebox, storing and retrieving song information. The original project was of a simple design and had opportunities for improvement. I decided to convert this original project into a fullstack web-based application.

Converting this original program into a fullstack application not only let me develop my current skills, but it also let me learn more about JavaScript, TypeScript, CSS, HTML, and MongoDB. While most of these topics were covered in previous coursework, the practical implementation was rather limited.

Throughout this application development, I gained valuable experience in team collaboration, stakeholder communication, data structures and algorithms, software engineering, and secure coding. In previous courses, as well as in this program development, I have learned to use Version Control Systems, like GitHub, in order to store, track, and maintain progress throughout development. During the original application development, I used GitHub to work alongside my classmates on the same project. Each of us contributed to the overall program, while being able to monitor and review each other’s work through GitHub.

Throughout development of the current application, I completed a series of narratives. These narratives described my weekly progress, challenges, and outcomes. These narratives were written with a wide range of readers in mind; some of which may be non-technical. My writing style was modified, to make sure the information was still conveyed and received appropriately, even by non-technical readers.

This enhancement of the previous application greatly helped me further develop my skills around data structures and algorithms. I gained hands-on experience setting up, configuring, and connecting to a MongoDB database. I also learned how to cross-reference database records, which reduces redundant data. I created mongoose schema to define the data structures, and paired those with controller files, which executed the manipulation of the data. I made sure to use efficient algorithms when parsing, passing, and retrieving data. Only the data that was needed was accessed, without unnecessarily passing any other data. Some information was parsed from ObjectIds, reducing the need for additional data retrieval.

Developing this application from start to finish taught me a lot about software engineering. I learned how important it is to thoroughly plan the data structure, database structure, classes, and UI. By thoroughly identifying the needs of every relationship and function, valuable development time can be reduced. I successfully created frontend and backend frameworks, using routes, CORS and an HTTP client to allow the two to communicate.

I built dozens of JavaScript, TypeScript, and HTML files, resulting in a greater understanding of their architecture and functionality. I implemented functions that worked with the current frameworks of the application and removed those that didn’t. For example, I began using the NgZone library to trigger page refreshes when the data changed. This didn’t always work with every page though, so instead I began using the ChangeDetectorRef library. This library was much more reliable and resulted in the desired functionality.

I implemented error handling across the application, ensuring that a majority of problems were appropriately caught and handled. This reduced the number of silent crashes. I also used asynchronous functions, in order to maintain a free-flowing data stream. Without these, communication between the server or components could be delayed if a particular function is taking a long time to finish processing.

Finally, secure coding principles were implemented. I used the Express-rate-limiter, CORS, and Helmet libraries to ensure safe program function. Because this is a web-based application, these libraries protect from cross-origin requests, rapid brute force attacks, and HTTP injection attacks. Along with user credentials, this helps create a secure application. An AuthGuard file was used, to limit page access to only those with the proper credentials. Lastly, any connection credentials or JSON web tokens were stored in a .env file, ensuring their security.

Skills implementation

I decided to use the MEAN stack framework (MongoDB, Express, Angular, Node.js) for my enhanced project, not only because of the wide range of skills needed to write such a program, but also due to its popularity in professional software development. Not only was the application now a fullstack program, but I also added much more functionality than the original application.

When first developing the application, I set up a MongoDB database. This database stores all the document information, such as artists, albums, users, etc. I gained valuable hands-on experience creating a database, configuring connections, and using object references to reduce data redundancy. I stored the database connection credentials in a .env file and put it in a .gitignore file, to protect them from being exposed.

I used Mongoose to create schemas to maintain consistent data structures. I learned how to use MongoDB ObjectIds to cross-reference other records. Because of this referencing, I also needed to use the populate() function in my controller files, to correctly retrieve the data to display, rather than only displaying the raw ObjectId. I used the built-in Mongoose function, timestamps, to be able to read and display when a document was created and updated. This helps streamline the codebase and improve the user experience.

Once the database was created, I created the Express server within the application. This file contains the Express import, as well as other important libraries. I used Mongoose for communication with MongoDB, CORS for cross-origin communication between the frontend and backend, Dotenv for secret keeping, Express-rate-limit to protect against brute-force attacks, and Helmet to provide secure HTTP headers. Using these libraries allows for efficient communication between the frontend, the server, and the database.

I also included route handling within the Express file. These routes handle incoming requests and send them to the appropriate file. In this program, I used an MVC framework. The functionality is split between models, views, and controllers. The routes link these components, allowing for efficient processing. Having each function in its own file also makes the codebase easier to debug and make changes.

The frontend development gave me valuable practice using TypeScript and HTML. Each page of the application has its own Angular component, consisting of a TypeScript file, HTML file, and CSS file. I began development with the TypeScript files for each component, since this is where the functionality is based. I learned about, and implemented, many different libraries throughout the frontend development process. I used CommonModule to enable NgFor and NgIf functionality in the HTML files. These functions let me add more dynamic control to the pages.

I made extensive use of FormBuilder, FormGroup, Validators, and the ReactiveFormsModule. These were used to create and validate forms. These forms were used on pages where users can add or edit songs, albums, playlists, and artists. The Validators library added built-in validation to form input, reducing the need for additional verification in the TypeScript file or backend.

I also used the Router and RouterLink libraries to implement navigation and routing. These libraries allowed me to easily use links in my HTML files and to redirect the user to the appropriate pages. ForkJoin was another important library. This let me retrieve multiple sets of data at the same time, which made the processing time much faster.

When the same functionality was needed across the application, I created shared services. Each document type (artist, song, etc.) used its own shared service. These services could be called from any file and then communicate with the backend to perform common functions, such as getting one record, getting multiple records, updating a record, or deleting a record.

Two additional services were created for this application: SessionService and ConfirmDialogService. Rather than creating the same code on every page, these services were called when needed. The SessionService stored user login information in local storage, maintaining the user’s logged in status across all pages. The ConfirmDialogService displayed a window to the user, asking them to confirm deletion. Once confirmed or declined, the result was sent back to the original caller file, and processing continued.

The HTML files were the other file in each frontend component, and these determined how data was displayed. I used the Bootstrap library to quickly implement consistent styling across all pages. I learned how to pass dynamic values, iterate over arrays, and use if/else statements to handle displays based on variables. I used if/else statements to dynamically display a ‘Loading’ message if the data had not yet been received. This made sure to let the user know that the system was still processing.

I learned a great deal about software development throughout my degree program, as well as while creating this application. This final project demonstrates competency in the following areas:

  • Use Version Control Systems
  • Create and communicate with a MongoDB database
  • Create Express and Angular components
  • Style pages with HTML and Bootstrap
  • Properly safeguard connection secrets
  • Send and receive secure HTTP requests
  • Implement efficient algorithms
  • Employ MVC architecture

Artifact

Jukebox

Originally developed in CS-310 - Collaboration and Team Project

The original assignment was a partially completed jukebox-style program, written in C++. The program stored information about songs, artists, students, and playlists. The user could search for a playlist by name and the playlist would be displayed to the user. The program was created in February 2026 and modified over the following weeks.

I chose this artifact because it presented many opportunities for improvement. First, I had the opportunity to take the C++ program and convert it into JavaScript. Also, the current functionality was extremely limited, and the data was hardcoded into the program files. Additionally, the program was only able to run on a local machine. There was no connectivity to the web or other users. These opportunities left me wanting to turn this program into a full stack web application. Turning this into a full stack web application required a variety of skills across many different frameworks. I developed full backend functionality, created a database, and developed the frontend components.
